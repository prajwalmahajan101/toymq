# v3 M5 journal — TUI v3: cluster view

**Branch:** `feat/tui-v3`, off `main` (base `2f030f6`)
**Goal:** render a live cluster pane in `toymq-tui` — press `c` to see role,
leader, term, log offsets, and (on a leader) a per-peer match-index/lag table,
fed by `INFO replication` and refreshed on a poll. Leadership changes must be
reflected in the view; all v2 keybindings must still pass.
**ADR:** none — consumes v3 M3 (`ClusterClient`, ADR 0032) and v3 M4 (`INFO
replication`, ADR 0033).
**Dogfooding:** [`docs/TOYRAFT-MIGRATION-REPORT.md`](../docs/TOYRAFT-MIGRATION-REPORT.md)
(v3 M5 section — `Status()` polling ergonomics; FRICTION-07 confirmed from the
display side).

## What I did

**TUI — new `stateClusterView`, all in `cmd/toymq-tui/`.**
- `brokerConn` interface gains `Info(ctx) (client.ReplicationInfo, error)` — both
  `*client.Client` and `*client.ClusterClient` already implement it, so the wiring
  was a one-line interface add, no client-side change.
- `c` (in `stateMain`) enters the pane; `esc`/`c` leaves; `q`/`ctrl+c` quits.
- Live refresh via a self-perpetuating `tea.Tick` (`clusterPollInterval = 1s`).
  Each entry bumps `pollGen`; `clusterInfoMsg`/`clusterPollTickMsg` carry the gen
  and are dropped on mismatch, and the tick only re-arms while
  `state == stateClusterView`. So rapid `c` toggling can't strand overlapping
  tickers and a lingering tick can't poll after the pane is closed.
- `renderClusterView` reuses `scrollbackStyle`; hand-rolled aligned peer columns
  (no `bubbles/table` dep, matching the existing hand-rolled scrollback). Handles
  standalone ("no cluster"), follower (peer detail is leader-only → shows role +
  leader hint), and poll error.

**Tests — pure `Update`/`View`, no new dep.**
- `TestUpdate_CKeyOpensClusterView`, `TestUpdate_ClusterEscReturnsMain`,
  `TestUpdate_ClusterInfoStoredAndStaleDropped`,
  `TestUpdate_ClusterPollTickReArmsOnlyWhenOpen`.
- `TestUpdate_ClusterLeaderChangeReflected` — the owned-risk test: feed a leader
  `INFO`, then a follower+new-leader `INFO`, assert `View()` reflects `follower`
  and the new leader id.

## Problems I faced

- **Ticker leak on toggle.** A naive `tea.Tick` re-armed on every tick would
  spawn a second live ticker each time `c` was pressed. Fixed with the `pollGen`
  generation counter gating both the info result and the tick re-arm.
- **`teatest` deviation.** Roadmap named a `teatest` 3-node smoke, but `teatest`
  is not a dependency and the `newRoutedCluster` harness lives in an `internal`
  `_test.go` unreachable from `cmd/toymq-tui`. Met the owned-test *intent* with a
  pure-model test; recorded the deviation in ROADMAP and left `teatest` as a
  documented upgrade path.
