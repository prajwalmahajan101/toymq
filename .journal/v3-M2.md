# v3 M2 journal — Multi-node replication + leader election

**Branch:** `feat/cluster` (M2a distributed core, then M2b partition-heal +
linearizability), off `main`
**Goal:** a real N-node `--replicate` cluster: every mutating command replicates
`Propose → Apply` to all followers, writes are leader-gated, and the cluster
survives a leader kill *and* a network partition with zero acked-write loss. M2
owns failover safety, split-brain prevention, and the linearizability check.
**ADRs:** [0030](../docs/adr/0030-cluster-mode-peer-transport.md) (M2a — peer
transport, membership, NOTLEADER gate),
[0031](../docs/adr/0031-partition-heal-linearizability-harness.md) (M2b —
partition-heal + linearizability harness) ·
**Dogfooding:** [`docs/TOYRAFT-MIGRATION-REPORT.md`](../docs/TOYRAFT-MIGRATION-REPORT.md)

## What I did

**M2a — the distributed core.**
- **Multi-node transport** — swapped M1's no-op transport for toyraft's
  `pkg/transport/http` over real peer URLs. `toymq --replicate --peers
  id@url,… --raft-addr host:port` forms a 3/5/7-node cluster; empty `--peers`
  keeps the M1 single-node path byte-for-byte.
- **Membership on the CLI** — `internal/config` parses `--peers` into a
  string-keyed `map[id]url` (`ParsePeers`/`ClusterPeers`/`PeerURLsExcludingSelf`)
  so config stays free of a toyraft import; `cmd` converts to `raft.NodeID` at
  assembly. Validation: self ∈ peers, odd N, `id@absolute-url`, no dup, raft-addr
  set.
- **Leader-gated writes** — a mutating command on a follower returns
  `*raft.ErrNotLeader`; the broker exposes it via `NotLeaderHint`, the session
  maps it to a new wire code `NOTLEADER <leader-id>`. Reads stay local
  (documented non-linearizable; the read model is M3).

**M2b — partition-heal + linearizability harness.**
- **Test-only partition seam** — `partitionableTransport` decorates the transport
  with an atomic blocked-peer set, dropping `Send`-to and `Step`-from a blocked
  peer (bidirectional). `newCluster` wraps every node. Lives in the test package,
  not `internal/replication` — fault injection is a test concern.
- **`TestClusterPartitionHealNoLoss`** — isolate the leader alone (minority of 1),
  prove it cannot ack a write, the majority of 2 elects and serves, then heal →
  the minority truncates its uncommitted tail and converges. Zero acked loss.
- **`TestClusterLinearizablePubConsume`** — a `porcupine` message-queue model over
  concurrent PUBs under one-node partition churn; no acked PUB lost, no
  double-consume.

## Problems I faced

**A dead peer stalled the whole cluster — the M2a liveness bug.** toyraft's driver
calls `Transport.Send` **synchronously** in its single driver goroutine, and the
http transport's `Send` is a blocking POST. So one dead/slow peer froze the
driver: no ticks, no commits, no election. The fix had to be an **async send
decorator** (`internal/replication.asyncTransport`): each peer gets a buffered
queue + pump goroutine, `Send` enqueues and returns, dropping on a full queue
(raft's Send is best-effort — a dropped append is retransmitted next tick).
Mandatory for liveness, not an optimization; filed upstream as FRICTION-04.

**A kill is not a partition — M2a couldn't test split-brain.** `node.Stop()`
removes one side, so there is never a live minority; the "minority must not ack"
and "divergent tails reconcile on heal" invariants were untestable. M2b needed a
fault where both sides stay alive. That's the `partitionableTransport` — and the
inbound drop matters: a one-way (Send-only) block would still let the isolated
node *hear* the majority and never campaign, so the drop is bidirectional
(`Send` by `msg.To`, wrapped `Step` by `msg.From`).

**Proving no split-brain without hanging the test.** An isolated leader's
`Propose` appends locally but never reaches quorum, so a plain `Publish` blocks
forever. toyraft's `Propose` selects on `<-ctx.Done()`, so a **bounded**
`PublishCtx` on the isolated leader cleanly returns `ctx.Err()` — the assertion is
"this write must fail", no hang, no phantom ack. On heal, raft log-matching
truncates the isolated leader's uncommitted tail with zero embedder involvement —
divergent-tail reconciliation is automatic.

**The linearizability harness flaked on CI under `-race` (Go 1.26.x only).**
First green locally and on Go 1.25.x, but 1.26.x failed convergence:
`n2=20, others=23 after 30s`. Not a data race — a budget problem. A node that
campaigns while isolated rejoins with a **higher term**, forces one re-election,
and a lagging follower only catches up once a stable leader heartbeats it; 30s on
a shared `-race` runner was unlucky. Fix (`c158023`): widen the churn healed
window past `ElectionTimeoutMax` so a just-un-isolated node catches up before the
next isolation, wait for a single stable leader before starting the convergence
clock, and raise the budget 30s → 60s. Green on both Go versions.

**Porcupine soundness vs at-least-once writes.** A `ctx`-cancelled `Propose` "may
still commit later", so a timed-out publish can land in the log without being in
the acked set. Asserting `acked == log` would flake. The model only admits
leader-acked publishes into the history and checks the acked set is a **subset**
of the converged log (no acked write lost) — never equality. At-least-once from
the client's view is a documented raft property, not a bug.

## Outcome

`toymq --replicate` forms a 3/5/7-node cluster that replicates every write,
gates writes to the leader, and survives both a leader kill and a network
partition with zero acked-write loss and no split-brain. M2a suite + M2b
(`TestClusterPartitionHealNoLoss`, `TestClusterLinearizablePubConsume`, porcupine)
green under `-race` on Go 1.25.x and 1.26.x; CI green; merged (PR #29). The v3 M2
exit criteria are met. Deferred by design: NodeID→client-addr resolution + client
auto-retry + read redirect (M3); multi-partition linearizability and a full
concurrent-consumer live history (v4). Dogfooding back to toyraft: FRICTION-04
(sync-driver liveness) is the headline M2 finding, plus the confirmation that
partitioned `Propose` + ctx-cancel and heal-time log truncation behave exactly as
`rc.3` documents.
