# v3 M3 journal — Client routing: write redirect + read model

**Branch:** `feat/cluster-routing`, off `main` (base `becc34c`)
**Goal:** an any-node client transparently completes every write and reads
consistently from the leader — resolve the `ERR NOTLEADER <node-id>` hint
client-side and retry, and make a follower redirect SUB to the leader by default
with an opt-in stale-read escape hatch. M3 owns the client-facing half M2
deferred: hint resolution + retry, and the leader-default read model.
**ADR:** [0032](../docs/adr/0032-client-routing-read-model.md) (client routing:
write redirect + leader-default read model) ·
**Dogfooding:** [`docs/TOYRAFT-MIGRATION-REPORT.md`](../docs/TOYRAFT-MIGRATION-REPORT.md) (v3 M3 section + FRICTION-05)

## What I did

**Server — leader-gate SUB + broaden the redirect class.**
- `Broker.IsLeader()` next to `LeaderHint` — `raft == nil || Status().Role ==
  Leader`. Standalone is always leader, so standalone SUB is byte-identical.
- `SUB <topic> <consumer> STALE` — parser accepts an optional 4th `STALE` token
  into `SubCommand.Stale` (any other 4th token still rejected); `handleSub`
  redirects a default SUB off a follower with `ERR NOTLEADER`, `STALE` bypasses.
  ACK/NACK stay leader-gated (unchanged from M2).
- `Broker.NotLeaderHint` now matches three raft errors, not one:
  `*raft.ErrNotLeader` **plus** `raft.ErrProposalDropped` and `raft.ErrStopped`.

**Client — typed error + redirecting wrapper.**
- One `serverErr(frame)` helper classifies every ERR frame; `pub/sub/flow/create/ack`
  all route through it. `NOTLEADER` → typed `*NotLeaderError{Hint}` (matched with
  `errors.As`), `TRANSPORT` → `ErrTransport`, else `ErrServer`.
- `backoff.go` — bounded exponential + full jitter, injectable rand/sleep (~20 lines,
  no new dep).
- `ClusterClient` (`cluster.go`) — one live connection to the believed leader,
  mirrors `Pub`/`PubDelay`/`Ack`/`Nack`/`Create`/`Sub`/`SubStale`/`Err`/`Close`.
  Seeded with `id@host:port` members; on a redirectable error it resolves the hint
  to a member (id map, else round-robin sweep), reconnects, and replays the op,
  bounded by the backoff attempt cap. `SubStale` subscribes against the connected
  node without redirect.
- `Client.SubStale` — SUB with the STALE flag; `Client.Sub` unchanged.

**CLI + TUI.** `-cluster id@host:port,…` on `toymqctl` (all subcommands via a shared
`brokerConn` interface + `connFlags.dial`) and `toymq-tui`; `--stale` on `toymqctl
sub`. A single `-addr` keeps the direct `client.Dial` path (standalone unchanged).

## Problems I faced

**Routing around a *dying* leader needs more than `ErrNotLeader`.** The kill-test
(`TestClusterClientConvergesAfterLeaderKill`) failed: after `node.Stop()` the old
leader's `Propose` returns `raft: node stopped or not started`
(`raft.ErrStopped`), which the server surfaced as `PUB_FAILED` — a
command-specific error the client does **not** retry, so the write never
converged. First attempted fix was gating on `IsLeader()` in `sendIfNotLeader`,
but `Status().Role` on a stopped node still reports `Leader` (stale), so it never
fired. Root cause: `NotLeaderHint` only matched `*raft.ErrNotLeader`. The real
fix classifies `ErrProposalDropped` (leadership lost mid-propose) and `ErrStopped`
(node stopping) as redirectable too — both are the same actionable condition from
the client's view. These carry no hint, so they fall back to `LeaderHint()`, and
an empty/self hint makes the client sweep — redirect converges regardless. Filed
upstream as FRICTION-05 (a `raft.IsNotLeader(err)` predicate would save every
embedder this rediscovery).

**Mid-write leader death is a transport error, not a NOTLEADER.** When the
connected leader dies under an in-flight op the client sees `ErrTransport`/
`ErrClosed`, not `*NotLeaderError`. The first `redirectLoop` only retried on
`NotLeaderError`, so a transport failure surfaced immediately and the wrapper
stayed glued to the dead connection (`conn()` kept returning the closed client).
Fixed by retrying on transport/closed too — advance to the next member — while a
genuine op error (validation, dup) still surfaces. `ErrClosed` from `conn()`
itself (the ClusterClient was closed) short-circuits so a closed wrapper does not
spin to the attempt cap.

**Interface refactor broke a nil-client TUI test.** Widening the TUI model's
`client` field from `*client.Client` to a `brokerConn` interface turned the test
helper's untyped `nil` into a nil *interface*; taking the method value
`m.client.Err` then panicked (SIGSEGV at `update.go:47`). Passing a typed
`(*client.Client)(nil)` restores the method value (nil receiver, deferred to call
time) without touching production code.

## Outcome

An any-node `toymqctl -cluster …` / `toymq-tui -cluster …` completes every write
and lands SUB on the leader via transparent redirect; `--stale` reads
follower-local state. Standalone (`-addr`) is byte-identical. Unit (`-race`):
backoff bounds/jitter/abort, parser STALE accept/reject, `NotLeaderError` via
`errors.As`. Integration (`internal/server/cluster_routing_test.go`, `-race`,
real 3-node cluster of `server.New` listeners over the raft harness): a
follower-seeded `ClusterClient` completes `Create`/`Pub`/`Sub` via redirect, a
follower `SubStale` serves local state while a default SUB is redirected, and
writes converge after a mid-run leader kill under bounded retry. Full suite green
under `-race`; `go build ./... && go vet ./...` clean. v3 M3 exit criteria met.
Deferred by design: auto-resubscribe after mid-stream failover and the
bounded-staleness `MAXLAG` contract (both v4). Dogfooding back to toyraft:
FRICTION-05 (no single "cannot serve as leader" predicate) is the M3 finding;
otherwise routing is entirely client-side and surfaced no toyraft friction.
